# 0.3.0 行動評価：条件による判断の切り替え

実施日：2026-11-19。対象：64枚の決定カードを含む 0.3.0、コミット `a837cc149ab1f4f84efab8e54882f76947aa3de4`。

**初回24入力は23件合格、1件判定不能、0件不合格。** 判定不能の1件は入力の文脈を明確にし、新しいセッションで追加試験を行って合格した。初回24/24合格とは集計しない。

## 方法

各入力を新規セッションで実行。評価エージェントには指定入力とスキル資料のみを与え、判定基準・他の入力・前の回答は渡さなかった。主担当が回答本文と使用資料を照合し、事前の基準で判定。

skill-creator の Independent Forward-Testing 手順を使用。評価には凍結した `SKILL.md`・決定カード・出典要約を与え、評価ケースの期待結果を含む `evaluation/` は渡していない。凍結資料の全ファイルを公開済みローカル資料とバイト比較し、同一であることを確認した。各資料と回答の SHA-256、入力、判定基準、回答全文は [results.json](results.json) に保存した。

実行環境はCodexの独立評価サブエージェント。厳密なモデルIDは取得していない。CLIのログイン制約があり、Claudeモデルの実測ではない。採点者は主担当1名。

## 判定不能となった入力

P030Bの「内部のアルゴリズムまで全て表に出すべき？」には、プレイヤーに公開する意味と、開発用のデータ表へ移す意味がある。回答は前者を仮定し、開発向けの解釈にも短く触れた。想定していた後者の比較を十分に検証できなかったため、判定不能とした。

追加入力P030BRは「攻撃力などの調整値をデータ表へ外出しする作業中です。内部の制御アルゴリズムも全て、その調整用の表へ移すべきでしょうか？」。新しい評価セッションにこの入力と同じスキルだけを与え、初回回答や期待する結論は渡していない。

## 修正の判断

今回確認できたのは入力の曖昧さであり、スキル本文や決定カードに普遍的なルールを追加する根拠は得られなかった。スキルは0.3.0のまま維持する。P030Bの元入力と追加入力は両方保存し、意図に合わせて事後に元の回答を合格へ変更しない。今後同じ比較を実施する際は、データ表への外出しという文脈を含める。

M2では、回答に使われた125が閲覧記録の検索対象名にない点を再確認した。申告された「098の見出しと後続30行」には125の本文も含まれ、記載内容も回答と一致した。漏読や捏造とは判定しなかった。

## この結果から言える範囲

原型とPV、探索と正式提出、家庭内対戦とランク対戦、導入と任意練習など、選択した条件対照では異なる判断を出し分けた。未確認の原発言や時刻を要求する入力では捏造しなかった。これは選択した入力での観察であり、全カードに追加が不要であることや、命中率が原版より向上したことを証明するものではない。

- 各入力1回の選択試験であり、123入力全件の試験ではない。
- 原版との比較、反復による安定性測定、Claudeモデルでの動作試験は行っていない。
- Claude CLIとCodex CLIのモデル実行用ログインがなかったため、独立評価サブエージェントを使用。
- 原動画・原字幕は照合していない。出典の正確さはリポジトリのAI要約に対する確認範囲。
- スキルを明示的に使う助言の試験であり、自動起動やClaudeの配布・インストール試験とは別。
- 判定は主担当による1回の定性的レビューで、独立した複数採点者の一致度は測定していない。
