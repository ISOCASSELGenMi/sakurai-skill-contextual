# 企画・伝達・作業の進め方

<a id="market-data-or-concept"></a>
## market-data-or-concept：市場の傾向に合わせるか、独自の狙いを選ぶか

- 問題：市場の傾向に合わせるか、独自の狙いを選ぶか。
- 適用状況：新規企画、既存ファン向け企画、対象者の定義、売上説明にデータを使う場面。
- 出典要約：既存市場のデータだけでは新しい道を示せない一方、商売上の用途はある。ニッチと広い入口の選択、見た目や過去作との競争も扱う。
  - 出典：[pr.md](../references/pr.md) の 224「ターゲティングとマーケティング」、[mindset.md](../references/mindset.md) の 112「価値観の幹と枝先」、[graphics.md](../references/graphics.md) の 150「絵はゲームの楽しさに関係ある?」、[mindset.md](../references/mindset.md) の 196「競争と豊穣」。
- 判断案（編集上の解釈）：誰のどんな欲求に応えるかと、事業説明に必要な情報を分け、未検証の魅力は試して確かめる。
- 適用外・導けないこと：市場調査を全廃する根拠にしない。年齢や性別のラベルだけで好みを決めつけない。既存の売れ筋の模倣を成功保証にしない。
- 関連・対立：[original-or-familiar](systems.md#original-or-familiar)、[show-gameplay](development-pr.md#show-gameplay)。
- 根拠の状態：AI 要約のみ・原動画未照合。条件の整理と比較手順は編集上の解釈。

<a id="presentation-or-catalog"></a>
## presentation-or-catalog：全情報を並べるか、相手に伝わる順番を作るか

- 問題：全情報を並べるか、相手に伝わる順番を作るか。
- 適用状況：企画書、実演、公式サイト、参戦映像の説明順と情報量を決める場面。
- 出典要約：プレゼンのテンポと密度、図中心の企画書、階層化した情報、実演の見せ場、映像の段階的監修を扱う。
  - 出典：[mindset.md](../references/mindset.md) の 012「プレゼンはスピード」、[mindset.md](../references/mindset.md) の 038「企画書の書き方」、[mindset.md](../references/mindset.md) の 052「企画は強火でザッと仕上げる」、[pr.md](../references/pr.md) の 141「ウェブサイト」、[pr.md](../references/pr.md) の 161「参戦ムービー」、[pr.md](../references/pr.md) の 205「人の目の前でゲームすること」。
- 判断案（編集上の解釈）：相手が判断したいことから、見せ場と補足への入口を組む。資料と実演を実際の順序で通して理解を確認する。
- 適用外・導けないこと：全資料を図一枚・文二行に固定しない。既存作品を知る相手と初見の相手で同じ説明を前提にしない。
- 関連・対立：[explore-or-commit](planning-change.md#explore-or-commit)、[show-gameplay](development-pr.md#show-gameplay)。
- 根拠の状態：AI 要約のみ・原動画未照合。条件の整理と比較手順は編集上の解釈。

<a id="start-or-prepare"></a>
## start-or-prepare：考え続けるか、小さく作って確かめるか

- 問題：考え続けるか、小さく作って確かめるか。
- 適用状況：制作に入れない学習者、方向を試す試作と、大量の後工程へ進む判断。
- 出典要約：自作して反応を得ること、手を動かす習慣、仮の絵と動きによる検証、長期動画制作でのパイロット確認を挙げる。
  - 出典：[planning.md](../references/planning.md) の 034「ゲーム作りで食っていくには」、[mindset.md](../references/mindset.md) の 083「とにかくやれ!!」、[tech.md](../references/tech.md) の 117「ファミリーベーシック」、[misc.md](../references/misc.md) の 100「初代『星のカービィ』開発秘話」、[misc.md](../references/misc.md) の 259「最終回スペシャル（チャンネルの作り方）」。
- 判断案（編集上の解釈）：今確かめたい問いを一つ選び、完成・観察できる小さな成果を作る。本制作への投資は検証結果と制約で判断する。
- 適用外・導けないこと：今すぐ着手を、許可や重要な前提を飛ばして大規模制作する根拠にしない。動画制作の進め方をそのままゲームへ固定しない。
- 関連・対立：[prototype-or-pv](development-pr.md#prototype-or-pv)、[scope-or-quality](production.md#scope-or-quality)。
- 根拠の状態：AI 要約のみ・原動画未照合。条件の整理と比較手順は編集上の解釈。

<a id="effort-or-sustainability"></a>
## effort-or-sustainability：仕上げに手をかけるか、続けられる負担にするか

- 問題：仕上げに手をかけるか、続けられる負担にするか。
- 適用状況：品質を上げる追加作業、定期発信、制作習慣、効率化を判断する場面。
- 出典要約：遊び手の目的を基準にすること、無意味な苦労を避けた効率化、定期作業の負担を抑える習慣、入出力と自己への働きかけを扱う。
  - 出典：[mindset.md](../references/mindset.md) の 007「遊びの仕事は遊びじゃない」、[mindset.md](../references/mindset.md) の 021「お客さんに説明できるの？」、[mindset.md](../references/mindset.md) の 067「苦労は忘れる､作品は残る」、[mindset.md](../references/mindset.md) の 098「なぜコラムを続けられたのか」、[mindset.md](../references/mindset.md) の 125「インプットを太く､アウトプットも太く」、[mindset.md](../references/mindset.md) の 169「暗示の力」、[mindset.md](../references/mindset.md) の 210「言ったことはそうなっていく」。
- 判断案（編集上の解釈）：成果に効く手間と、続ける頻度・負担を分け、短い周期で確かめる。締切や励ましは本人に合う方法を選ぶ。
- 適用外・導けないこと：努力量を品質の証拠にしない。精神論で休息や個人差を無視せず、特定の習慣を全員に強制しない。
- 関連・対立：[scope-or-quality](production.md#scope-or-quality)、[private-idea-or-public-update](distribution.md#private-idea-or-public-update)。
- 根拠の状態：AI 要約のみ・原動画未照合。条件の整理と比較手順は編集上の解釈。

<a id="standard-or-exception"></a>
## standard-or-exception：共通ルールを守るか、作品固有の例外を設けるか

- 問題：共通ルールを守るか、作品固有の例外を設けるか。
- 適用状況：操作の標準、色や表示の統一、プラットフォーム等の外部要件と狙いが競合する場合。
- 出典要約：統一ルールが理解を助ける一方、複数のガイドラインや表現の制約が衝突する点を扱う。標準操作とスキップ等の利便性にも助言がある。
  - 出典：[misc.md](../references/misc.md) の 137「ガイドライン」、[planning.md](../references/planning.md) の 173「知っていることは話が早い」、[ui.md](../references/ui.md) の 178「必ず飛ばせるように、止められるように」。
- 判断案（編集上の解釈）：実際に適用される規則、社内の慣習、設計上の好みを分ける。強制要件は現行の所有者資料で確認し、狙いを満たす代替を比較する。
- 適用外・導けないこと：動画要約を現行の規約や法的要件より優先しない。例外を独断で許可したことにせず、規則の現在の内容を推測しない。
- 関連・対立：[standard-or-custom-input](controls.md#standard-or-custom-input)、[story-or-control](onboarding-difficulty.md#story-or-control)。
- 根拠の状態：AI 要約のみ・原動画未照合。条件の整理と比較手順は編集上の解釈。
