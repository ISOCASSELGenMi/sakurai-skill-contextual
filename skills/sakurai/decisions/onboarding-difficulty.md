# 導入と難易度

<a id="tutorial-or-practice"></a>
## tutorial-or-practice：本編で教えるか、練習場を設けるか

- 問題：早く遊びたい気持ちと、操作の習得を両立する。
- 適用状況：初回導入と、複雑な技を練習する任意のモードを区別する。
- 出典要約：[planning.md](../references/planning.md) の 085「自然なチュートリアル」は、練習らしさを抑えて実戦の流れで教えるとする。[specs.md](../references/specs.md) の 171「How to Play」は、何もない練習場を批判する一方、操作しながら技術を学ぶモードの必要性も述べる。
- 判断案（編集上の解釈）：初回の必須導入は短い実践に組み込み、反復習得が目的なら任意の練習環境を検討する。最初のプレイまでの時間と、説明なしで行動できる割合を観察する。
- 適用外・導けないこと：練習モード全般の禁止とは解釈しない。初見で理解できない操作を、説明を省くためだけに放置しない。任意・必須による整理は編集上の解釈。
- 関連・対立：085 と 171。物語が主目的の導入は [story-or-control](onboarding-difficulty.md#story-or-control)。
- 根拠の状態：AI 要約のみ・原動画未照合。

<a id="story-or-control"></a>
## story-or-control：物語を見せるか、早く操作を返すか

- 問題：感情移入と、操作したい気持ちをどう配分するか。
- 適用状況：アクションの冒頭、物語中心の作品、再プレイで条件が異なる。
- 出典要約：[planning.md](../references/planning.md) の 017「とにかくゲームさせてみて」は早く本編に入ることを勧め、231「ゲーム内ムービー」は長さ自体の善悪ではなく掘り下げの役割も挙げる。[gameplay.md](../references/gameplay.md) の 026「ゲーム性以外の面白さ」は物語を進める面白さを認める。[ui.md](../references/ui.md) の 178「必ず飛ばせるように、止められるように」はスキップと一時停止を求める。
- 判断案（編集上の解釈）：何を楽しむために来た人かを確認し、物語の理解や感情の変化に必要な場面かを点検する。初見と再見を分け、操作開始の早さだけで物語中心の作品を評価しない。
- 適用外・導けないこと：017 の時間目安を全ジャンルの不合格基準にしない。物語重視という理由だけで停止・送り・スキップの必要性を無視しない。
- 補足出典要約：冒頭を見せ場から始める助言と、読み進める速度をプレイヤーが選べる設計もある。ノベルの楽しさと区別して検討する。
  - 出典：[ui.md](../references/ui.md) の 209「テキストの読み進め」、[planning.md](../references/planning.md) の 233「最初にクライマックスを」。
- 関連・対立：017・231・026。入力への反応は [impact-and-tempo](player-experience.md#impact-and-tempo)。
- 根拠の状態：AI 要約のみ・原動画未照合。

<a id="difficulty-or-assistance"></a>
## difficulty-or-assistance：難しさを維持するか、救済を設けるか

- 問題：達成感を保ちながら、進行不能や離脱を減らす。
- 適用状況：初心者向け、挑戦重視、難易度変更が可能な作品を分ける。
- 出典要約：[gameplay.md](../references/gameplay.md) の 146「ゲーム性を上げると、一般性が下がる」は対象者に合わせたリスクを勧める。211「クリアできないよりマシ」は難易度変更やスキップ等の救済と、厳しい路線を選ぶ場合の限界を挙げる。041「悪魔の窯」は自動的な難度低下の利点と、常に限界を求められる負担を両方記載する。
- 判断案（編集上の解釈）：どこで詰まり、何を学べず、何を失うかを調べる。救済の提案、任意の練習、別ルート等を比較し、救済を使う心理的負担も観察する。挑戦重視なら、その約束と救済の関係を明示する。
- 適用外・導けないこと：全員が初回で成功すべきとも、全員が自動難度調整を望むとも言えない。開発者がクリアできることは初心者向けの根拠にならない。
- 関連・対立：041・146・211。対戦の実力差は [randomness-and-handicap](player-experience.md#randomness-and-handicap)。
- 根拠の状態：AI 要約のみ・原動画未照合。

<a id="retry-or-consequence"></a>
## retry-or-consequence：再開を早くするか、失敗の重さを残すか

- 問題：再挑戦を促しながら、失敗と学習の意味を保つ。
- 適用状況：短い反復挑戦、ローグライト、長い進行の巻き戻しでは失うものが異なる。
- 出典要約：[gameplay.md](../references/gameplay.md) の 116「リトライは迅速に」は操作復帰を早める一方、無思考の無限復活や復活直後の連続死を避けるとする。127「やり直しに見合う魅力はあるか？」は、同じ場所を反復する人にも先への期待を見せる必要を挙げる。
- 判断案（編集上の解釈）：失敗から入力可能までの時間と、失う進行量を別々に測る。待ち時間を減らしたうえで、復帰地点の安全、学習できる情報、反復中の変化を検討する。
- 適用外・導けないこと：迅速な再開はペナルティ全廃と同義ではない。ローグライトというジャンル名だけで長い反復の魅力を保証できない。
- 補足出典要約：敗北で緊張から解放される可能性と、その理由の仮説を挙げる。全ての敗北が快感になると証明されたものとしては扱わない。
  - 出典：[gameplay.md](../references/gameplay.md) の 097「やられるとスッキリする?」。
- 関連・対立：116・127。停止演出との比較は [impact-and-tempo](player-experience.md#impact-and-tempo)。
- 根拠の状態：AI 要約のみ・原動画未照合。
