# 体験版と発信

## demo-or-main：体験版を作るか、本編の完成を優先するか

- 問題：認知・試遊の効果と、別配布物の制作・保守コストを比較する。
- 適用状況：イベント向けの限定試遊、公開配布、本編の発売前後で必要な品質と範囲が違う（編集上の整理）。
- 出典要約：[pr.md](../references/pr.md) の 121「体験版」は、認知への効果と、別版管理・漏洩対策・デバッグ・調整不足による悪評のコストを挙げる。080「広報はかけ算」は認知の必要性を示す。
- 判断案（編集上の解釈）：誰に何を確かめてもらうかを先に決め、範囲、更新、対応可能な不具合、公開の時期を見積もる。映像・実演で同じ目的を達成できるかも比較する。
- 適用外・導けないこと：全員に体験版が必要とも、個人制作には作れないとも言えない。出典の工数表現を各プロジェクトの固定見積もりにしない。
- 関連・対立：121・080。映像を選ぶ場合は `prototype-or-pv`、`show-gameplay`。
- 根拠の状態：AI 要約のみ・原動画未照合。

## private-idea-or-public-update：構想を温めるか、進捗を発信するか

- 問題：構想を仕上げる集中と、完成像を知ってもらう継続発信を分ける。
- 適用状況：未整理のゼロからの企画と、公開できる開発情報を持つ段階を区別する（編集上の解釈）。
- 出典要約：[mindset.md](../references/mindset.md) の 142「内圧をカンカンに高める」は、構想を書き上げる前の発散で熱量を失う点を挙げる。[pr.md](../references/pr.md) の 243「スマブラ拳」は、継続更新で見に来る習慣を作る事例と、担当・監修の負担を記載する。
- 判断案（編集上の解釈）：企画を整理する作業と、公表する素材を作る作業を分ける。発信段階なら、無理なく続けられる頻度、伝える内容、監修時間を決める。
- 適用外・導けないこと：142 をすべての開発相談や公開の禁止にしない。243 の平日毎日更新を、全チームが守る義務にしない。二つの要約の境界は原動画で確定したものではない。
- 関連・対立：142 と 243。公開映像の中身は `show-gameplay`。
- 根拠の状態：AI 要約のみ・原動画未照合。段階による整理は未確認の解釈。
