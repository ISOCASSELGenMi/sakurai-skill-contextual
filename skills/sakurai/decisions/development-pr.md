# 開発と広報

## prototype-or-pv：原型と PV のどちらを先に作るか

- 問題：限られた制作時間を、遊びの検証と外部への説明のどちらに使うか。
- 適用状況：工程間の優先順位を決める相談。検証の進み具合、提出先、期限、映像の目的で判断が変わる（この条件整理は編集上の解釈）。
- 出典要約：
  - [concepts.md](../references/concepts.md) の通し番号 027「大乱闘スマッシュブラザーズ」では、先にプロトタイプを作って社内評価を得た開発経緯を記載している。
  - [pr.md](../references/pr.md) の 080「広報はかけ算」は、開発と広報を両輪として扱う。
  - 同ファイルの 184「ゲーム画面を見せてくれ!」は、宣伝映像の早い段階でゲーム画面を見せる助言である。
- 判断案（編集上の解釈）：
  - 遊びが成立するか未検証なら、その不確実性を減らす小さな原型を候補にする。
  - 遊びが検証済みで、直近の課題がストアや出資者への説明なら、既存の遊びを伝える映像を候補にする。
  - 両方が必要なら、それぞれの期限と必要な成果を比較する。未実装の構想を説明する映像なら、完成ゲームの実写記録とは区別して提示する。
  - 状態が不明なら、何を検証済みか、誰に何のために見せるかを確認する。
- 適用外・導けないこと：027 は個別作品の経緯であり、原型を必ず先に作る普遍的な順序ではない。184 の「早く見せる」は映像内の構成であり、開発工程で PV を先に作る指示ではない。ここから桜井氏の「原型か PV か」の一律の答えは確定できない。
- 関連・対立：同ファイルの `show-gameplay`。両者は決定する対象が異なる。
- 根拠の状態：AI 要約のみ・原動画未照合。上の条件付き優先順位は今回の改版で加えた解釈。

## show-gameplay：宣伝映像の冒頭で何を見せるか

- 問題：見込みプレイヤーが、どんな遊びかを短時間で理解できるようにする。
- 適用状況：特に新規 IP・インディーの宣伝映像（出典要約に明記）。
- 出典要約：[pr.md](../references/pr.md) の 184「ゲーム画面を見せてくれ!」は、長いロゴ・世界観紹介などより早いゲーム画面を勧め、著名シリーズ・著名作者のティザーや、処理に偽りのないテックデモを例外として挙げる。101「製品像は正しく伝える」は、売り場で見せる製品像と実際の中身の一致を求める。
- 判断案（編集上の解釈）：その映像を初めて見る人が「何を操作し、何が面白いか」を理解できるか確認する。知名度による例外を新規 IP に自動適用せず、冒頭の実プレイ映像を比較候補にする。
- 適用外・導けないこと：すべての映像の構成を固定する根拠ではない。素材を作る順序や開発着手順序は `prototype-or-pv` で扱う。
- 関連・対立：`prototype-or-pv`、同じ出典の 101。商品の正確な説明と期待づくりを両立させる。
- 根拠の状態：AI 要約のみ・原動画未照合。
