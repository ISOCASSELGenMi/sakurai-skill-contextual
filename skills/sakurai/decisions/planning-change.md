# 企画案と制作中の変更

## explore-or-commit：選択肢を広げるか、一案を提出するか

- 問題：案出し、正式提案、没案の記録をどう使い分けるか。
- 適用状況：仕様の問題解決・アイデア探索と、提出する企画書・仕様書の相談。
- 出典要約：
  - [mindset.md](../references/mindset.md) の 029「仕様を変えること」は、選択肢を並べ、短期と長期の両面で最適解を選ぶとする。
  - 同ファイルの 235「アイデアが出ないとき」は、実現性による選別を後にして案を広げるとする。
  - 同ファイルの 109「プランBに頼るな」は、企画書・仕様書に A 案・B 案を並べず、考え抜いた一手を出すとする。一方、問題発生後の検討で別案へ戻ることは認めている。
  - [concepts.md](../references/concepts.md) の 158「大乱闘スマッシュブラザーズSPECIAL」には、企画書に没案も書くと記載されている。
- 判断案（編集上の解釈）：探索中は複数案を比較し、正式提案では選んだ案と理由を明確にする。「採用案の選択を読み手へ丸投げすること」と「選択済みの案に没案の記録を添えること」は区別できる可能性がある。
- 適用外・導けないこと：109 を根拠に案出しや比較検討を禁止しない。158 の没案の記録目的は要約だけでは確定できない。この区別で両資料の矛盾が完全に解消したとは断定せず、記録目的が重要なら原動画を確認する。
- 関連・対立：109 と 158 を一緒に確認する。`concept-or-change` は、案の選定後に問題が出た場合を扱う。
- 根拠の状態：AI 要約のみ・原動画未照合。「没案記録と並列提案の区別」は未確認の解釈。

## concept-or-change：コンセプトを守るか、仕様を変えるか

- 問題：制作中に問題が見つかったとき、何を維持して何を変更するか。
- 適用状況：方向の迷い、実装後の発見、変更に伴う工数や士気の損失がある開発。
- 出典要約：[mindset.md](../references/mindset.md) の 185「コンセプトは貫くもの」は魅力の核を灯台にたとえ、途中で曲げることやスクラップ＆ビルドを戒める。029「仕様を変えること」は変更のコストを指摘する一方、作って初めて分かることへの柔軟さを求める。
- 判断案（編集上の解釈）：目指す体験の核と、その実現手段である仕様を分け、観察された問題に対して必要な変更と波及範囲を比較する。核自体に疑問があるなら、既存の狙いを維持した検証と変更案を比べ、判断材料を得る。
- 適用外・導けないこと：185 は検証で得た問題を無視する根拠ではなく、029 も際限なく作り直す許可ではない。「核と手段を分ければ常に両立する」は編集上の仮説であり、どこまで核を変えられるかは要約から確定しない。
- 関連・対立：185 と 029。採用案の比較には `explore-or-commit`。
- 根拠の状態：AI 要約のみ・原動画未照合。核と手段による整理は編集上の解釈。
