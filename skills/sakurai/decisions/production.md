# 判断と制作運営

<a id="decide-or-investigate"></a>
## decide-or-investigate：その場で決めるか、調査を先に行うか

- 問題：判断待ちを減らしながら、誤った情報で方向を固定しない。
- 適用状況：判断材料が揃った会議と、結論を変える情報が欠けた会議を分ける。
- 出典要約：[team.md](../references/team.md) の 189「決断を先送りにするな」は即決に加えて、正確な材料の事前準備と誤りに気づいた後の再判断を求める。[mindset.md](../references/mindset.md) の 156「無意味な多数決」は、決定者に正しい情報が必要で、スタッフが問題・解決案を出すとする。
- 判断案（編集上の解釈）：選択肢、決定者、欠けている判断材料を明確にする。材料が揃えば決定し、不足が結論を変えるなら必要な調査と再判断の時点を決める。戻せる仮決定も候補にする。
- 適用外・導けないこと：即決を根拠に確認不能な事実を作らない。調査を無期限の保留にしない。「戻せる仮決定」は編集上の候補であり、桜井氏の定型手順ではない。
- 関連・対立：189・156。案の比較は [explore-or-commit](planning-change.md#explore-or-commit)。
- 根拠の状態：AI 要約のみ・原動画未照合。

<a id="scope-or-quality"></a>
## scope-or-quality：要素を追加するか、削って完成させるか

- 問題：魅力の核を保ち、期限・工数内で完成させる。
- 適用状況：遅延、予算超過、兼任・連携の負担、追加要素の依存関係。
- 出典要約：[team.md](../references/team.md) の 256「ディレクターは切る仕事」は、重い要素を削って進路を修正し、問題を早く共有するとする。088「10人チームは7人分」は管理・調整による制作量の減少を挙げる。[concepts.md](../references/concepts.md) の 108「大乱闘スマッシュブラザーズX」は、一人用モードの追加が大きな別制作に相当する例を述べる。
- 判断案（編集上の解釈）：追加で必要になる素材、実装、調整、翻訳、検証を含めて比較する。核への寄与と依存関係を見て削減候補を出し、小さな完成形を検討する。
- 適用外・導けないこと：088 の比率や 108 の工数感を、別の規模の見積式にしない。核を損なう削除を単なる項目数の削減で正当化しない。
- 補足出典要約：開発中止の判断を、今後の費用と見込みの釣り合いから説明する。個別企画の利益を要約だけで予測せず、具体的な条件を確認する。
  - 出典：[misc.md](../references/misc.md) の 110「開発中止」。
- 関連・対立：[concept-or-change](planning-change.md#concept-or-change) と併読。延期か削減かは実際の制約で判断する。
- 根拠の状態：AI 要約のみ・原動画未照合。

<a id="exhaustive-or-targeted"></a>
## exhaustive-or-targeted：総当たりで確認するか、危険な組み合わせを狙うか

- 問題：確認できる量と、見逃した場合の影響を踏まえて検証を配分する。
- 適用状況：小さく列挙できる仕様と、組み合わせが膨大なゲームを区別する。
- 出典要約：[team.md](../references/team.md) の 135「デバッグは終わらない」は総当たりの限界と不具合が出やすい処理を挙げる。206「デバッグの体制」は版の統一、再現手順、優先度、担当への返却と再確認を扱う。[specs.md](../references/specs.md) の 229「オンラインアップデート」は、発売後の修正が必要でも初回体験を良くする努力を求める。
- 判断案（編集上の解釈）：列挙可能な部分は確認し、全体では影響が大きい状態遷移やデータ破損につながる箇所を優先する。修正の周辺を再確認し、未確認の範囲を記録する。
- 適用外・導けないこと：総当たり不能を確認不要に読み替えない。発売後に直せることは、既知の重大不具合を放置する根拠にはならない。確認完了と不具合ゼロを区別する。
- 関連・対立：135・206・229。削減判断は [scope-or-quality](production.md#scope-or-quality)。
- 根拠の状態：AI 要約のみ・原動画未照合。検証配分は編集上の提案。
