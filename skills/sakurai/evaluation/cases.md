# 条件を変えた動作確認

## 確認方法

各入力を別の会話で、このスキルと必要な資料だけを与えて実行する。回答案や下の判定基準は評価側に保持し、回答を生成する側へ渡さない。現実の変更や投稿は不要。
表現の一致ではなく、適用条件、行動、根拠の区別を評価する。複数回試す場合も回数と失敗を記録し、未実施のテストを実施済みにしない。

| ケース | 入力 | 判定基準 |
|---|---|---|
| A1 | 核心の遊びが成立するか未検証。来週まで外部提出はない。今週は原型と PV のどちらを作る？ | 原型による検証を有力候補とし、184 を開発順序の根拠にしない。今回の優先順位は独自の提案と示す。 |
| A2 | 核心の遊びは試遊で検証済み。来週ストアを公開し、説明映像がまだない。今週は原型と PV のどちらを作る？ | 説明映像を有力候補とし、A1 の結論を機械的に流用しない。 |
| A3 | 原型と PV のどちらが先？桜井氏の絶対の答えだけ教えて。 | 一律の原発言を捏造せず、検証状態・映像目的など結論を左右する情報を確認する。 |
| B1 | まだ探索中の仕様。A 案と B 案の利点を比較してほしい。 | 109 を理由に比較を拒まず、029・235 等の条件と照合する。 |
| B2 | 明日正式な企画書を提出する。A 案と B 案をどう載せる？ | 推奨案を明確にする提案をし、比較検討そのものは禁止しない。 |
| B3 | 109 はプラン B を否定するのに、158 は没案も載せる。矛盾していない？ | 両出典を確認し、記録と並列提案の区別を解釈として示す。原動画未確認のまま完全解決を断言しない。 |
| C1 | 家族で遊ぶ対戦。初心者が毎回最下位で参加しなくなった。逆転補正は必要？ | カジュアル目的に合う候補として補正を検討する。 |
| C2 | 実力を測るランク対戦。負けている側の攻撃力を強めるべき？ | C1 と同じ補正を自動適用せず、公平性・納得感を検討する。 |
| D1 | ヒットは派手だが、画面切替の長い暗転がつらい。さらにヒットストップを増やすべき？ | 問題の場所を切り分け、遷移の待ちを扱う。手応え改善の固定順序で停止を増やさない。 |
| D2 | 待ち時間はないが、攻撃が当たったことに気づきにくい。何を試す？ | 認識を強める音・ポーズ・短い停止等を候補にし、効果の比較方法を示す。 |
| E1 | 原片を確認していないなら、184 の発言をそのまま引用し時間位置も教えて。 | 要約と直接引用を区別し、URL や時間位置を作らない。原資料確認か確認できない旨を示す。 |
| F1 | キャラ強化が報酬になるソロ RPG を考えている。設計を見て。 | 149 の強化と進展の役割を検討する。 |
| F2 | 公平な対戦ゲームで、100 時間育成すると攻撃力が倍になる報酬を入れたい。設計を見て。 | F1 を流用せず、参加負担と公平性を検討し、別の報酬を比較する。 |
| G1 | キャラクターが背景に埋もれる。桜井流で改善案を。 | カードがないことを理由に止まらず、graphics 等の該当要約を読み、作品の視認性から提案する。 |

| H2 | 対戦経験者が難しい技を繰り返し練習する任意のモードが欲しい。 | H1 を流用して練習場を禁止しない。目的と条件を区別する。 |
| I1 | 物語を読むことが目的のノベルなのに、3 分以内に戦闘を入れるべき？ | 026・017・231 の目的を比較し、戦闘を強制しない。 |

## 記録すること

実行日、利用モデル、ケース ID、回答または保存先、読まれた根拠、条件に沿った判断の可否、出典と解釈の混同、未解決点を記録する。
このケース集を置いただけでは命中率の改善は証明されない。原版との比較には同じ入力・モデル条件・試行回数を用いる。
